# 창원 인구 월별 후속 수집·비율 재계산 v3.7.3

> 이 문서는 이전 버전입니다. 현재 v3.7.4의 광화동 검증·장애 회복·남은 12개월 실행은 [수정 안내](POPULATION_RECOVERY_V374.md)를 참고하세요.

## 실행

1. GitHub 저장소 → Actions로 이동합니다.
2. **Changwon population follow-up and ratios v3.7.3**을 선택합니다.
3. **Run workflow → main → Run workflow**를 누릅니다. 별도 입력은 없습니다.
4. 2024-09부터 2026-08까지 24개 작업이 시간순으로 이어집니다.
5. 마지막 **Verify all periods and population-only ratios** 결과를 확인합니다.

이 액션은 수동 실행 전용입니다. 코드 반영만으로 장시간 수집이 시작되지 않습니다.
GitHub 서버에서 실행되므로 실행을 시작한 뒤 사용자 PC를 켜 둘 필요는 없습니다.

## 9시간 이상 이어 실행하는 방식

GitHub-hosted runner의 단일 job은 최대 6시간입니다.
https://docs.github.com/en/actions/reference/limits

본 액션은 24개 월별 job을 순차 연결합니다. 각 job은 최대 100분이고,
마지막 재계산 job은 최대 60분입니다. 전체 설정상 상한은 41시간이며
단일 job 제한을 넘기지 않습니다. 9시간 이상 실행 가능하다는 뜻이지,
완료 후에도 의도적으로 9시간을 채우거나 API 장애에도 무한 반복한다는 뜻은 아닙니다.
실측한 한 달 약 24분을 단순 적용하면 24개월 약 9시간 36분이며,
설치·저장·재계산·지연에 따라 실제 시간은 달라집니다.

## 월별 처리

- 시·5개 구 인구/남녀/세대 합계와 원본 수집 출처를 재확인합니다.
- 이미 검증·저장된 월은 원본 재수집을 건너뜁니다.
- 미완료 월은 204개 법정읍면동 및 하위 법정리 코드 317개,
  인구·연령·1인세대 세 API를 단일 월 조건으로 조회합니다.
- 조회 완료 전에는 해당 월의 인구 보완을 저장하지 않습니다.
- 공식 총계와 일치하는 계획만 월별 Firestore 배치에 저장합니다.
- 저장 후 모든 population patch를 다시 읽어 일치 여부를 검사합니다.
- 성공한 월과 이에 영향을 받는 다음 달/다음 해 같은 달의 인구 지표를 계산합니다.
- 비교 월의 총계가 미검증이면 변화율은 null로 남깁니다.
- 성공한 빈 원본 응답은 null로 보존합니다. 실제 0과 구분합니다.

재계산 필드: 인구·세대 전월/전년 대비, 청년 비율, 고령 비율 및 대용지표 표시,
1인세대 비율, 청년/고령 1인세대 비율, 자료가 모두 있는 경우 1~2인세대 비율.
60세 이상만 제공되면 65세 이상으로 표시하지 않고 proxy 메타정보를 보존합니다.

`derived` 전체를 교체하지 않고 해당 인구 필드만 갱신합니다.
매매·상권 등 다른 derived 필드와 4개 종합지수는 보존합니다.
종합지수 재계산 필요 표시도 해제하지 않습니다.

## 중단 및 재개

- 60분 내부 작업 예산, 요청/재시도 시간 확인, 70분 별도 프로세스 제한.
- 요청은 연결 5초·응답 읽기 20초 제한, 재시도 최대 1회.
- 연속 실패 6회, 요청 제한/권한 오류, 프로세스 시간 초과는 후속 월을 정지합니다.
- 한 달의 데이터 검증 문제는 별도 기록하고 다음 독립 월을 시도합니다.
- 월별 캐시는 같은 월에만 재사용하며 재사용 전에 원본의 코드·월·버전을 검증합니다.
- 다시 Run workflow를 누르면 월별 Firebase 저장값과 원본 출처를 다시 확인합니다.
  완료된 월의 수집을 반복하지 않고 미완료 월과 계산만 이어 갑니다.
- 전체 writer concurrency group을 점유하여 기존 인구/비인구 수집과 동시에 쓰지 않습니다.

Artifacts `changwon-population-YYYY-MM-RUN_ID`는 해당 월의 원본, 진행 기록,
총계 및 저장값 대조, 인구 지표 계산 결과를 담습니다.
마지막 `changwon-population-final-RUN_ID`의 `population_derived_final.json`을 확인합니다.

전체 완료: `status: complete`, `remaining_months: []`, `mismatches: []`.
`needs_continue`/실패는 전체 완료가 아닙니다. 성공 월은 이미 저장되어 있습니다.
최종 보고서는 월별 저장 지역 수와 인구값이 있는 지역 수를 따로 명시하므로,
48개월 총계 통과를 모든 개별 값이 존재한다는 뜻으로 해석하지 않습니다.
비인구 수집이나 4개 종합지수의 최종 확정 완료도 의미하지 않습니다.
