## 광화동 조사 결과

공식 API 원본을 2026-10-12 다시 조회했습니다.
2025-09 광화동(4812912400) 인구 API: 727명, 남 366명, 여 361명, 333세대.
연령 API는 동일 코드·월·빈 행정동/통/반에 대해 두 행을 반환했습니다.

| 원본 시도명 | 인구 | 남성 | 여성 |
|---|---:|---:|---:|
| 서울특별시 | 726 | 366 | 360 |
| 경상남도 | 1 | 0 | 1 |

첫 행의 시도명이 법정코드와 모순됩니다. 정상적인 서울/경남 지역 구분이라고
단정하지 않습니다. 원본은 수정하지 않고 이름 필드 이상으로 기록합니다.
기존 식별키는 시도명 등의 원본 구분 필드를 포함하지 않아 두 행을 충돌로 판단했습니다.
원본 라벨이 다른 수치 행은 별도로 검증하며, 완전 동일 행은 한 번만 사용합니다.
라벨만 다르고 수치가 동일하거나 동일한 전체 식별키에 서로 다른 값이 있으면 계속 차단합니다.

두 연령 행의 10세 구간 합계, 남녀 합계를 각각 확인한 뒤 별도 인구 API와 대조했습니다.
합계 727명, 남 366명, 여 361명으로 일치했습니다.
30~39세 여성 1명을 포함한 행이며 청년 인구(20~39세)는 163명입니다.
자료 연결은 공식 법정코드가 기준입니다. 지역명을 서울로 바꾸거나 원본을 덮어쓰지 않습니다.
통합 월 저장은 다른 모든 지역을 포함한 시·5개 구 총계 검증도 통과해야 가능합니다.

## 실패 자료 보존

- `failed_original_SOURCE_CODE_MONTH.json`: 실패 당시 원본과 구체적 검증 이유.
- `failed_cached_SOURCE_CODE_MONTH.json`: 기존 캐시 검증 실패 원본.
- 실패 자료는 정상 캐시와 분리하고 재사용하지 않습니다.
- 오류 문자열과 원본의 자격증명 필드는 공통 redaction으로 제거합니다.
- `source_metadata_warnings` 및 source의 `metadata_warning`에 이름 이상을 기록합니다.

## 일시 연결 장애

기본 연결 제한 15초, 응답 읽기 제한 60초. 각 요청은 재시도 최대 1회입니다.
연속 일시 실패 6회가 발생하면 30초 대기하고 단일 worker로 다음 원본 요청을 시험합니다.
회복은 월별 최대 2회이며, 전체 작업 시간도 계속 검사합니다.
회복 후에도 반복 실패하면 월을 보류하고 후속 실행을 정지합니다.
요청 제한(429/할당량)·권한·인증 등의 명시적인 오류에는 이 회복을 적용하지 않습니다.

## v3.7.5 추가 확인 및 보완

광화동 행 검증 통과 후, 2025-09 진해구 API 합계와 기존 행정동 총계 사이에
여성 1명·1세대 차이를 확인했습니다. 같은 기준월의 공식 법정동 CSV를 독립적으로
다운로드해 확인한 진해구 법정동 총계는 API 합계와 같은 185,762명·85,570세대입니다.
광화동 공식 법정동 CSV도 727명·333세대입니다.
시 전체 및 5개 구의 해당 월 공식 법정동 CSV 6개 총계를 모두 확인했습니다.
기존 기준표의 2025-09 시 전체와 진해구만 달랐습니다.

API 수치를 가감하거나 임의로 허용 오차를 설정하지 않았습니다.
`population_official_history_totals.json`의 해당 월만 독립 공식 법정동 기준으로 수정하고,
이전 행정동 기준은 `population_official_history_totals_admin_original.json`에 보존했습니다.
다른 47개월의 기준값은 변경하지 않았습니다.
법정동 CSV 원본(인코딩만 UTF-8로 변환)과 다운로드 해시·출처·변경 전후 값은
`data/population_legal_reference_202509` 및 기준표의 `reference_overrides`에 기록했습니다.

액션 표시 이름은 **Changwon population follow-up and ratios v3.7.5**입니다.
일시 연결 장애가 월별 제한 회복 후에도 지속되면, 2분 대기 후 새 실행 서버에서
같은 월을 한 번 더 시도합니다. 월별 캐시는 재사용합니다.
요청 제한·권한 오류, 수치/중복 검증 문제, 강제 프로세스 종료에는 이 재시도를 적용하지 않습니다.
첫 실행과 회복 실행의 캐시 키와 Artifact 이름을 분리하여 저장 충돌을 방지했습니다.
두 실행 모두 실패하면 더 이상 자동 반복하지 않고 후속 월을 중지합니다.
