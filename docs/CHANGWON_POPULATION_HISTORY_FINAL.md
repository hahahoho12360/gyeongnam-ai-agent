# 창원 과거 인구 보완 최종 액션 v3.7.1

## 수정 이유
2024년 8월 대산면의 9개 법정리 인구 합계는 6,706명이고 공식 대산면 총계는 6,708명이다. 기존 대산면 코드의 저장값은 여성 2명·2세대다. 기존 액션은 하위 리 합계로 읍·면 지표를 교체하여 읍·면 코드에 별도로 반환되는 자료를 제외할 수 있었다. 원본 읍·면 응답은 새 액션이 기존 공식 API로 다시 조회하며, 기존 저장값이나 차이 2를 임의 보정값으로 사용하지 않는다.

## 점검·저장 순서
1. 실제 Firebase 48개월 인구·남성·여성·세대 값을 공식 시·5개 구 총계와 먼저 대조한다. 과거 성공 표시만으로 건너뛰지 않는다.
2. 총계가 맞지 않는 월은 창원 204개 법정읍면동, 113개 하위 법정리, 총 317개 코드를 인구·연령·1인세대 3개 API로 조회한다. 모든 8개 읍면 부모 코드 및 최신월에 응답이 없던 법정동·법정리도 포함한다.
3. 3개월 범위 조회, 월별 응답 분리, 코드·월·중복·페이지 완결성 확인, 연령 합계와 인구 합계 확인을 수행한다. 범위 요청 실패 시 단월 요청으로 재시도한다. HTTP/API 오류는 no_data로 처리하지 않는다.
4. 읍면별 하위 리만 / 부모 코드만 / 하위 리+부모 코드 후보를 계산한다. 수치가 같은 후보는 중복 제거한다. 인구·남녀·세대 공식 구 총계를 모두 만족하는 후보 조합이 단 하나인 경우만 적용한다. 후보가 없거나 다른 값의 후보 둘 이상이 모두 맞으면 해당 월은 보류한다.
5. 예정된 남은 월 전체를 사전 점검한 뒤 통과한 월을 월별 원자 배치로 저장한다. 인구 관련 필드만 갱신해 부동산·상권 등 다른 수집 결과를 보존한다. 한 월의 요청/검증 오류가 다른 정상 월 처리를 중단하지 않는다.
6. 저장 후 다시 총계를 대조한다. 전체 48개월의 실제 저장 총계를 다시 확인한 후 파생지표·4개 지수를 재계산한다.

## 실행 방법
현재 비인구 액션 완료 후 GitHub Actions에서 **Changwon population history repair v3.7.1 final** 선택 → **Run workflow** → branch **main**, validation_policy **totals_first**, continuation_attempt **0**으로 실행한다. 이전 실패 실행의 Re-run jobs는 이전 코드를 실행할 수 있으므로 사용하지 않는다. Secrets는 기존 값을 그대로 사용한다.

작업 잠금은 기존 수집 액션과 같은 `changwon-population-repair`를 유지한다. 즉 동시에 쓰는 액션은 대기하며 실행 중인 액션을 취소하지 않는다. 6개 조회 작업을 병렬 처리한다. 작업 시간 한도는 330분이고 API 사전 점검 예산은 260분이다. 시간이 부족하면 통과 월을 저장하고 캐시를 보존하여 최대 3회 자동 후속 실행한다. 원본 API 결과는 Actions 캐시/Artifact에만 저장하며 Firebase에는 월간 집계만 저장한다.

## 결과 판독
- `history_status.json`의 **complete**: 48개월 인구·성별·세대 총계 검증과 지수 재계산 완료.
- **needs_continue**: 남은 사전 점검/재계산을 캐시에서 이어서 처리. 후속 실행은 최대 3회.
- **partial**: 정상 월은 저장했으나 원본 API 오류/모호한 집계/총계 불일치 월이 남음. 액션이 초록색이어도 전체 완료가 아님.
- **blocked**: 인증, Firebase 연결, 설정, 코드 기준표 등 실행 자체를 막는 오류. 서비스 장애까지 무조건 성공으로 만들지는 않는다.

`preflight_inventory.json`, `staged_validation_<월>.json`의 `parent_modes`, `preflight_issues.json`, `final_persisted_validation.json`을 확인한다. 빈 원본 응답은 null로 보존하고 경고하며 인구 0으로 바꾸지 않는다. `totals_first`는 과거 지역별 독립 CSV 대조가 아니라 공식 시·구 총계 및 API 내부 일관성 검증이다.

## 배포 전 검증 및 한계
첨부 실패 Artifact 원본 2,430건의 지역코드·월·중복을 재검사하고 실제 124개 지역·월 묶음의 3종 API 내부 일관성을 확인했다. 부모 잔여 응답, 부모 전체 합계, 모호한 집계, 성공한 빈 응답, 연령·성별·세대 불일치, 단월 재시도, 기존 비인구 필드 보존을 자동 테스트한다. 공식 현재 코드 목록의 모든 조회 대상 채택일은 분석 시작월 이전이다. 실행 환경에 서비스키가 없어 남은 25개월 전체의 신규 API 응답은 배포 전 확인하지 못했다. 그 검증은 Secrets가 있는 Actions의 저장 전 단계에서 실제로 수행한다. 새 액션의 조회 범위는 기존보다 넓으므로 기존의 6개월당 40분 소요시간을 그대로 적용할 수 없다.
