# 창원 인구 외 5개 소스 추가 수집 v3.9

인구 API를 다시 호출하지 않습니다. 기존 Firebase 인구·연령·1인세대 기록은 읽기만 합니다. 창원 법정 읍면동 204개와 공식 코드 목록이 정확히 일치해야 진행합니다. 경남 전체 546개 마스터를 수집 범위로 사용하지 않습니다.

## 승인 API 11개와 저장 소스의 관계

| 승인 API | Firebase 소스 | 이번 실행 |
|---|---|---|
| 공동주택 단지 목록 | apartment_basic | 목록 조회 후 단지별 기본정보 |
| 아파트 매매 일반 | apt_sale | 대체 API; 상세와 중복 합산하지 않음; 이번에는 호출하지 않음 |
| 법정동코드 | regions | 기존 공식 검증 목록과 Firebase 204개 대조; 새 코드 API 호출 없음 |
| 상가(상권)정보 | commerce | 현재 상태 1회 조회 |
| 아파트 전월세 | apt_rent | 미처리 지역이 있는 구·월 조회 |
| 아파트 매매 상세 | apt_sale | 미처리 지역이 있는 구·월 조회 |
| 건축물대장 | building_register | 현재 상태, 읍면은 하위 법정리 전체 합산 |
| 공동주택 기본정보 | apartment_basic | 목록에 있는 단지별 기본정보 조회 |
| 성·연령별 1인세대 | single_household | Firebase 처리 기록만 읽음 |
| 성·연령별 인구 | age_population | Firebase 처리 기록만 읽음 |
| 인구·세대 | population | Firebase 처리 기록만 읽음 |

API 승인 사실은 사용자가 제공한 목록에 근거합니다. API별 접근 권한을 실제 호출로 모두 시험했다는 뜻은 아닙니다. 일반 매매와 상세 매매는 같은 저장 소스에 연결되므로, 소스 저장 건수만으로 두 API 각각의 호출 이력을 증명할 수 없습니다. 보고서 `endpoint_access_tested: false`는 이 제한을 나타냅니다. 새 호출의 성공·실패는 수집 결과와 오류 보고서에서 확인합니다.

## 상태 구분

| 상태 | 의미 | 기본 동작 |
|---|---|---|
| unqueried / 미조회 | 출처 처리 기록과 해당 소스 값이 없음 | 보완 조회 |
| no_data / 자료 없음 | 정상적인 완전 조회 후 대상 지역의 행이 0개 | 재조회하지 않음; 인구나 거래가격을 0으로 채우지 않음 |
| stored / 저장 완료 | 출처 처리 기록과 해당 소스 값이 있음 | 재조회·덮어쓰기 생략 |
| legacy_unverified / 기존값 출처 미확인 | 값은 있지만 출처 기록이 없음 | 보존, 수동 검토 |
| conflict / 기록 충돌 | 자료 없음 기록인데 해당 소스 값이 존재 | 보존, 수동 검토 |

저장 완료는 기존 처리 기록이 있다는 뜻이며 기존 모든 값의 정확성을 새로 검증했다는 뜻은 아닙니다. 과거 API 오류는 자동으로 자료 없음으로 바꾸지 않습니다. 조회 실패는 `result.json.errors`에 소스·월·구/지역과 오류 유형을 기록하고 미조회 상태를 유지합니다. 서비스키가 URL에 들어갈 수 있어 원문 예외는 로그에 출력하지 않습니다.

`before.json`, `after.json`의 `matrix`에는 소스·월·지역별 상태가 있습니다. 거래 48개월을 지정하면 매매·전월세 각각 204×48건, 현재 스냅샷 3소스는 각각 204건입니다. 과거 48개월에 현재 상권·건축물·공동주택을 복제하지 않습니다. `snapshot`은 기존 분석 문서에 연결할 월이며 실제 관측일은 `freshness.sources[source].source_as_of`로 따로 보관합니다. 2026-09 문서에 연결해도 2026년 9월 당시 재고를 복원한 자료로 해석하면 안 됩니다.

## 실행 순서

1. GitHub Actions → **Changwon non-population audit and repair v3.9** → Run workflow.
2. 처음에는 `mode=audit`, 나머지 기본값 유지. Firebase 기록만 읽으며 공식 인구 API도 호출하지 않습니다.
3. `changwon-nonpopulation-audit-실행번호` 아티팩트에서 `before.json`과 `result.json` 확인. 미조회, 자료 없음, 저장 완료, 기존값 출처 미확인, 기록 충돌을 구분합니다.
4. 추가 저장하려면 같은 액션을 `mode=fill`로 실행합니다. `start=2022-10`, `end=2026-09`, `snapshot=2026-09`, `max_months=6`가 기본값입니다.
5. 인구 액션이 실행 중이면 fill 작업은 공유 저장 잠금 때문에 대기합니다. 점검 작업은 읽기만 하므로 먼저 실행할 수 있습니다. 한 번에 여러 fill 실행을 예약하지 마세요. GitHub concurrency는 모든 대기 실행을 보장하는 FIFO 큐가 아닙니다.
6. 완료 후 `changwon-nonpopulation-repair-실행번호`의 `result.json`에서 `applied`, `errors`, `remaining`, `needs_rerun`, `manual_review` 확인.
7. 미조회가 남으면 동일한 설정으로 재실행. 완료 기록은 건너뛰므로 남은 월부터 이어갑니다. 기본값은 거래 소스별 최대 6개 미처리 월입니다. 오류 없이 48개월이 모두 미처리였다면 최대 약 8번 실행이 필요하며 오류·부분 처리에 따라 추가 실행이 필요할 수 있습니다. 자동 연속 실행은 없습니다.
8. 미조회가 0이어도 기존값 출처 미확인·충돌·오류가 남으면 전체 검증 완료로 표시하지 않습니다.

## 저장 안전장치

- 구·월별 전체 거래를 조회하고 204개 공식 마스터로 매핑한 뒤, 미조회 지역에만 합계 저장. 구 전체 재조회가 필요한 경우에도 저장 완료 지역은 건너뜁니다.
- 응답 봉투, 페이지 총건수, 반복 페이지, 거래 기준월, 지역 매핑을 검사. 전체 응답의 한 행이라도 지역 연결이 불가능하면 그 조회 그룹은 저장하지 않습니다.
- 공동주택 kaptCode, 건축물 mgmBldrgstPk, 상가 bizesId로 중복 검사. 내용이 다른 동일 식별자는 오류로 처리합니다. 식별자가 없는 행도 임의 합산하지 않습니다. 거래는 강한 식별자가 없는 동일 값의 서로 다른 실제 거래를 함부로 중복 제거하지 않습니다. 취소된 매매는 제외합니다.
- 읍면 공동주택·건축물은 공식 법정동코드 목록에서 구성한 하위 법정리를 순회합니다. 목록에 있는 단지의 상세 조회가 실패하면 자료 없음으로 표시하지 않습니다.
- Firestore 트랜잭션으로 저장 직전에 해당 소스의 처리 상태를 재확인합니다. 기존 인구, 다른 소스, index_meta를 보존하며 5개 소스별 허용 필드만 반영합니다. 완료된 소스는 덮어쓰지 않습니다.
- 결과는 지역·월·소스 단위로 즉시 체크포인트가 됩니다. 중단 후 재실행하면 완료 기록을 건너뜁니다. 변경 월과 그 이후 기간의 파생값·창원 기준 지수를 재계산합니다. 중단 당시 지수 계산이 남은 문서도 재실행에서 처리합니다.
- 원본 행과 API 키를 Firebase에 저장하지 않습니다. 아티팩트에는 집계값과 상태만 보관합니다.
- 인구 보완, 일일·월간 수집, 최종화, cloud-rollout도 `changwon-population-repair` 잠금을 공유하도록 변경했습니다. 이미 실행 중인 구버전 작업·로컬 수동 스크립트·외부 앱은 이 새 잠금을 따르지 않을 수 있으므로 동시에 직접 실행하지 마세요.

## 확인 범위

로컬 테스트는 상태 구분, 인구 보존, 필드 소유권, 재실행 생략, 빈 응답, 페이지 누락/반복, 지역·월 불일치, 식별자 충돌을 검사합니다. 실제 API 응답과 Firebase 저장 확인은 사용자가 액션을 실행한 뒤 나온 보고서로 확정합니다. 이 변경을 올리는 것만으로 수집이 완료되는 것은 아닙니다.
