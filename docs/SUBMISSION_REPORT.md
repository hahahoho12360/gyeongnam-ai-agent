## 4. 개인 기록·대화·인증 실증

- Firebase 익명 계정 두 개로 배포 API 호출. 본인 기록 생성/목록/수정/요약/삭제 성공.
- 무인증 개인 API401, 타인 문서 GET/수정/삭제404, 다른 계정 목록에 미포함.
- 비율101 입력422. 실증 기록10·20을10·30으로 수정: 평균20, 최대30, 최소10, 상승.
- API 실증용 가상 기록·임시 대화는 검사 후 삭제했다. 공식 통계는 변경하지 않았다.
- 실제 홈페이지에서 명서동 청년21.21% 관찰 기록 저장·메모 수정·새로고침 후 유지 확인. 이 브라우저의 화면 증빙용 기록은 개인 자료이며 공식 통계가 아니다.
- 명서동 질문의 실제 GPT 답변18,425명/3,908명/21.21%, get_region_month 도구 입력2026-09 확인.
- 새로고침→삼정자동 선택→기존 명서동 대화 불러오기: messages·명서동 요약·도구기록 복원.

- 시스템 주입 보완 후 실제 개인 분석 요청도 HTTP200: 청년21.21%, 기록1건, 공식 통계와 구분한 GPT 답변과 저장·불러오기 확인. `system_context_live.json` 참조.

## 5. MCP와 도구 선택 근거

사용자 제공 Codex 화면에서 get_population_trend와 get_region_summary를 실제 호출한 기록을 확인했다. 입력은 region=4812510100, months=1, 결과2026-09/5,307명이다. Python MCP ClientSession으로 stdio 프로토콜도 별도로 확인했다.

웹은 질문의 지정월을 근거로 get_region_month를 선택한다. 통계 계산은 Python, 설명은 GPT가 담당한다. MCP는 로컬 stdio 서버가 Render의 동일 읽기 API를 이용한다. 외부 HTTPS `/mcp` 서버나 GPT Actions를 추가 배포한 것은 아니다.

## 6. 학습 목표를 설명하는 핵심 원리

1. 분석 흐름: 공식 API 페이지를 끝까지 조회→법정코드 연결→읍·면 하위 리 합산→지역×월 집계→총계 검증→Firestore 저장→읽은 값 재검증→요약/비율/지수→AI 설명.
2. 구조 분리: routers는 HTTP 경로·요청 처리, analysis/metrics/indexes는 계산, db는 저장, tooling은 도구 인터페이스, openai_agent는 GPT 왕복이다. 계층을 분리하면 같은 계산을 웹과 MCP에서 재사용한다.
3. Pydantic: 날짜·숫자·허용 항목·길이·지역코드를 검증하여 잘못된 요청이 DB로 들어가기 전에 거부한다. 업무 의미 검증(비율0~100 등)은 추가 함수가 담당한다.
4. Firestore: collection/document로 저장하며 개인 문서에 owner_uid를 붙인다. Admin SDK는 규칙을 우회하므로 서버에서 토큰·소유자 검사가 꼭 필요하다.
5. 컨텍스트 주입: 기록을 모델의 영구 학습에 넣는 것이 아니라 요청 때 SYSTEM 지침과 함께 요약을 전달한다. 요약·메모는 자료이며 그 안의 명령을 지시로 실행하지 않도록 구분한다.
6. CORS·환경변수: 브라우저가 허용된 프론트에서 API를 호출하게 하고, 키는 서버·Actions 환경에 둔다. CORS 자체는 인증이 아니므로 개인 API에 별도 인증을 적용한다.

| 지수 복구 | 같은 월 창원 비교집단 원자료로 지수를 재산출. 계산정보 누락과 실제 구성자료 부족을 구분 | `backend/indexes.py`, `tests/test_index_recovery.py` |
| 지도 | 선택·비교 4지역 경계·참고 면적, 확대·이동·큰 화면, 경계/도로·건물/지형·등고선 선택 | `frontend/region-map.js`, `tests/frontend/region-map.test.cjs` |

그래프 항목은 주민등록 인구, 청년 비율, 1인세대 비율, 주민등록 세대 수, 청년 인구 수(20~39세), 1인세대 수, 60세 이상 인구 수, 20세 미만 인구 수다. 20세 미만은 0~9세와 10~19세 합계다.

지수 재산출은 과거월에 최신 상권 자료를 복사하는 방식이 아니다. 선택한 월에 실제로 있는 구성자료로 계산하며, 유효 항목이 최소 2개보다 적으면 미산출로 유지한다. 월별 구성항목이 다르면 지수 증감의 해석에 그 차이를 알린다.

지도는 WGS84 경위도를 배경 타일과 같은 Web Mercator 좌표계로 표시한다. 면적은 화면상 넓이가 아닌 WGS84 타원체 계산값이다. 204개 지역 코드·명칭 대응을 확인했지만, 2023년 이후 경계가 바뀌지 않았다는 보증은 아니다. [지도 출처·재생성 방법](../frontend/data/BOUNDARIES.md)을 제공한다.

## 8. 한계와 평가자 재현 순서

스냅샷 자료는 과거 재고가 아니다. 거래가 없는 월의 가격과 최소 구성자료가 없는 지수는 비어 있다. 지수·상권활력은 프로젝트 대리지표이며 공식 순위나 인과효과가 아니다. 법정동과 행정동을 혼동하지 않는다.

Render 무료 서비스의 첫 요청/재배포 지연·일시502를 관측했다. 정상 재조회와 기능을 확인했으나 연속 가용성·부하 테스트는 하지 않았다. 자동 갱신의 누락 함수 오류는 코드에서 보완했으나, 실행 성공과 소스별 수집 완료는 별도로 확인해야 한다. 향후 자동 갱신 성공을 보장하지 않는다. 본 제출은 확인된48개월 자료와 수집·감사 실행에 근거한다.

평가자는 다음 순서로 확인할 수 있다.

1. 홈페이지에서 명서동을 조회하고 질문·답변·기준월을 확인한다.
2. 시작월·종료월을 바꾸고 표의 값·증감 및 8종 그래프 양 끝 값을 대조한다.
3. 지수 이름을 눌러 해설로 이동하고, 점수의 산출근거를 확인한다.
4. 지도 배경을 도로·건물과 지형·등고선으로 전환하고 4개 비교지역을 확인한다.
5. 개인 기록 1개를 저장·수정한 뒤 새로고침하고, 대화 목록에서 기존 대화를 불러온다.
6. CSV·JSON 내보내기, 다크 모드, Swagger 경로, MCP 증빙을 확인한다.

위성영상, 최신 경계의 완전성, 경남 전체 서비스, 업소 수의 장기 추세는 이번 완료 범위에 포함하지 않는다.

 비공개 GitHub이면 평가자 접근 권한이 필요하다. 최종 제출 버튼은 사용자가 과제 시스템에서 실행한다.
